## Design provenance

`tokens.json` extracts accent and dark palette values, chamfer size, card aspect, grid gap, and radius/spacing examples from `OSTTracker/Sources/Theme/Theme.swift`, `OSTTracker/Sources/Theme/Shapes.swift`, `OSTTracker/Sources/Views/RosterView.swift`, `DetailView.swift`, and `NowPlayingBar.swift`. The Swift app bundles Spotify Mix but the web app uses the required system font stack. The app has no light semantic palette; light colors are web-specific accessible equivalents.

## Passkeys status

The selected path is an application-owned WebAuthn ceremony using pinned `@simplewebauthn` packages. It verifies registration and sign-in on the server, stores only public credential material, requires user verification, and exchanges a verified passkey for a Supabase Auth session. Supabase's experimental passkey feature is not used. Host bootstrap, recovery-code issuance/use, credential removal/addition, and session revocation are implemented, but still need an authenticator-backed end-to-end drill on the permanent HTTPS domain. Do not register production passkeys until the permanent domain and RP ID are final.


### Reveal group rule

Form reveal groups only after the full tie-broken ranking. For a nonempty ranking, use `min(configured groups, entry count)` groups; each group except the last gets `floor(entries / groups)` entries and the last absorbs the remainder. Ties may cross a group boundary. This keeps groups nonempty and preserves the complete order.

### Scoring fixture expectation history

Expected ranking values follow the scoring specification, not observed code output. Two corrections were made during fixture construction: (1) the SHA-256 seeded draw ranks `low-spread-a` before `low-spread-b`; since reveal order is the reverse of rank, `low-spread-b` appears first among those tied entries in the reveal sequence; (2) the fixture's reveal groups were changed to fixed sizes after the user clarified that tie-breakers complete the order and reveal groups must not move tied entries. The latter changes group boundaries only; the complete ranking and score expectations are unchanged. The scorer excludes any withdrawn or incomplete rater, and assigns each included owner's entry an automatic 10. Neither correction was made merely to match implementation output.


### Visual audit

The home screen was reduced to its title, plain explanation, and direct actions. The three-icon feature row and “Private” badge were removed. Across the implemented routes, icons serve controls and navigation only; the site uses no decorative gradients, floating shapes, marketing card grid, emoji icons, delayed reveal animations, hosted font files, or bundled SF Symbols. Cards remain only where the OSTTracker roster/listening patterns need item boundaries. Recheck new screens against the brief before adding decoration.

### Demo listening-room visuals

- Choice: use one lazy R3F scene module for the intro sleeve shelf, explicit fullscreen vinyl player, and reveal; ordinary participant and host screens remain 2D. The 3D import starts only when a visitor flicks the intro shelf or opens the full player/reveal. Cap pixel ratio at 2, choose low-power WebGL, and fall back to CSS artwork for reduced motion, low-memory/low-core devices, or unavailable WebGL.
- Why: a 3D moment should explain the mystery record, audio playback, or rank. Keeping the 3D entry points explicit keeps the rating grid fast and avoids one WebGL context per card. Postprocessing was left out to preserve the mobile frame budget.
- Where: `components/demo/intro.tsx`, `components/demo/scene-viewport.tsx`, `components/demo/scenes.tsx`, `components/demo-app.tsx`, `app/demo/demo.css`.
- Change: keep generated art deterministic by entry ID, and keep every label, rank, player action, and reveal detail as accessible HTML. Add only a screen when it makes the requested experience clearer.
- CSP note: R3F's Canvas wrapper uses an inline style attribute to size its internal renderer. `style-src-attr 'unsafe-inline'` is enabled only for `/demo` (or for the isolated demo deployment); script execution stays nonce-only with `strict-dynamic`. Revisit if the Canvas renderer gains a CSP-compatible class-only wrapper.
- Assets: Three.js, React Three Fiber, Drei, and their Three typings are pinned and MIT-licensed. All demo art and sounds are generated locally; see `LICENSES`.
# Trial round

- Choice: a trial is a normal competition row with `is_trial=true`, configured for two entries per participant, one batch, one reveal group, 24-hour submission deadline, and 72-hour rating deadline. It uses the same submission, listening, rating, scoring, and reveal paths as a regular round.
- Why: friends can exercise the complete flow without mixing the practice round into prior-round reuse history. Trial data has an explicit host cleanup action that removes storage objects, unused invite identities, and the competition's dependent records; a separate append-only audit event remains.
- Where: `supabase/migrations/20261013220000_trial_round.sql`, host trial API/routes and `components/host-trial-management.tsx`.
- Change: adjust the preset in `private.host_create_trial()` and its deadline interval in `private.host_open_trial()`. Keep trial filtering in `private.list_host_submission_reviews()` so trial picks do not become later reuse history.
- Constraint: at most one non-archived trial exists, and a round can accept invites only while submissions are open and the combined participant plus outstanding invite count is below ten.
