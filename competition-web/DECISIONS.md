# Decisions

Record of implementation choices where the brief leaves room for judgment. Each row gives the choice, reason, code location, and a safe way to change it.

| Choice | Why | Where | How to change |
|---|---|---|---|
| Build the website in `competition-web/` on `feature/ost-competition-platform`; preserve the existing OSTTracker files and data. | Isolates the new platform and allows rollback. Mac integration is explicitly deferred to its own branch. | Repository branch and directory. | Cherry-pick the desired commits; create a separate integration branch from the resulting base for Swift changes. |
| Use Next.js App Router, TypeScript, Supabase Postgres/Auth/Storage, and a thin server-only data layer. No user-facing client calls may contain secret keys. | Matches the requested stack and keeps the policy boundary server side. | `competition-web/app`, `lib`, `.env.example` . | Replace adapters behind the domain interface without changing views. |
| Use the exact OSTTracker dark palette and add a neutral light palette because the Swift project currently defines dark colors only. | Web brief requires system light/dark; inventing light equivalents is preferable to silently forcing dark mode. | `tokens.json`, generated CSS. | Change source tokens and run `npm run tokens`; the `source` and `notes` fields record provenance. |
| Use Phosphor React icons in regular weight, sparingly; use only system fonts on web. | Its adjustable stroke weights and rounded optical style sit closer to SF Symbols than the prior icon set, while its MIT license permits use. No Apple symbol files are copied. | `package.json`, `app/`, `components/`. | Change the icon import and preserve accessible names; include its license in `LICENSES`. |
| Use application-owned WebAuthn ceremonies with Supabase Auth only for server-created account sessions. | Participants need no email and passkeys use the permanent site RP ID directly. | Server WebAuthn module and authentication API. | Keep registration disabled until production RP ID and recovery routes are complete and verified. |
| Bootstrap the single host from a trusted one-time CLI script using direct database access; let the website register only the first passkey against its short-lived token. | The brief forbids any website/API from granting host status. The CLI writes `private.platform_config`; a leaked bootstrap URL expires after ten minutes and cannot be reused. | `scripts/bootstrap-host.mjs`, `scripts/rotate-host-bootstrap.mjs`, host bootstrap routes, `private.host_bootstrap_tokens`. | Use `npm run host:rotate-bootstrap` from a trusted shell for controlled recovery while preserving the host ID. |
| Never include real anime audio in demo mode. Use a short Web Audio synthesized motif in-browser as original placeholder sound. | No unverifiable CC0 source is bundled, and no anime OST can be treated as demo-safe. | Demo audio module (planned). | Replace only with an original recording or a source whose license is listed and verified in `LICENSES`. |
| Production demo uses a separate host-only-cookie origin configured by `NEXT_PUBLIC_DEMO_ORIGIN`; the app route redirects there, and `/demo` strips cookies before rendering. Local development keeps `/demo` on the same origin for simpler testing. | A browser origin is the reliable boundary that prevents the real app's authentication cookies and sessions from being shared with demo code. | `app/demo/page.tsx`, `proxy.ts`, `.env.example`. | Deploy a second instance of this code without server secrets and set the permanent demo hostname before enabling friends' access. |
| Keep private pages uncached/noindex and send the same not-found response for forbidden and missing resources. | Avoid leaking competition existence in HTML, metadata, cache, or error behavior. | Security headers and server domain services (planned). | Any exception must retain privacy guarantees and be added to the security tests. |
| Connect the Next server through a dedicated `ost_web_app_login` account, then switch to a separate `NOLOGIN` `ost_web_app` role per transaction. | A server connection using the Supabase `postgres` owner could otherwise reset its role after an injection; a restricted login cannot elevate to the owner. | `lib/server/database.ts`, `scripts/bootstrap-local-db-role.sh`, `.env.example`. | Provision the same two-role boundary in the hosted project and use only the dedicated login URL. |
| Remove the optional `pg_graphql` extension in the separate competition project and expose only `public` to PostgREST. | The brief explicitly disables GraphQL and competition data must not gain an alternate query surface. | Competition foundation migration and `supabase/config.toml`. | Re-enable only after a separate security review and policy test suite. |
| Use the host as a participant; one server-controlled host identity only. | Matches the brief and avoids participant-controlled role claims. | Private config row and authorization functions in the Supabase migrations. | Change only by direct database administration, never through app or public metadata. |
| Participants join with a nickname and passkey; no real email is collected. | The invite URL is delivered by the host directly. Supabase Auth requires an email-shaped identifier, so the server generates a random `@participants.invalid` identity that cannot receive mail. | `app/api/host/invites/route.ts`, invite enrollment, `private.invites.email`. | Keep the reserved `.invalid` domain and never expose this internal identifier in UI or DTOs. |
| Reveal publication asks for passkey confirmation once per reveal group; live advancement publishes one entry per host action. | A per-entry ceremony would interrupt a live reveal and is not required by the requested assurance window. | Demo reveal state now models a confirmed group; production publish API remains to be implemented. | Use a five-minute verified assertion window instead if group sizes become dynamic. |
| Keep visitor progress only in a versioned sessionStorage key and clear older demo states when the interaction model changes. | Prevents stale simulated passkey/reveal fields from breaking the demo after an update; it contains no real data. | lib/demo/mock-api.ts. | Increment the key version when the demo-state shape changes. |

## Design provenance

`tokens.json` extracts accent and dark palette values, chamfer size, card aspect, grid gap, and radius/spacing examples from `OSTTracker/Sources/Theme/Theme.swift`, `OSTTracker/Sources/Theme/Shapes.swift`, `OSTTracker/Sources/Views/RosterView.swift`, `DetailView.swift`, and `NowPlayingBar.swift`. The Swift app bundles Spotify Mix but the web app uses the required system font stack. The app has no light semantic palette; light colors are web-specific accessible equivalents.

## Passkeys status

The selected path is an application-owned WebAuthn ceremony using pinned `@simplewebauthn` packages. It verifies registration and sign-in on the server, stores only public credential material, requires user verification, and exchanges a verified passkey for a Supabase Auth session. Supabase's experimental passkey feature is not used. Host bootstrap, recovery-code issuance/use, credential removal/addition, and session revocation are implemented, but still need an authenticator-backed end-to-end drill on the permanent HTTPS domain. Do not register production passkeys until the permanent domain and RP ID are final.


### Reveal group rule

Form reveal groups only after the full tie-broken ranking. For a nonempty ranking, use `min(configured groups, entry count)` groups; each group except the last gets `floor(entries / groups)` entries and the last absorbs the remainder. Ties may cross a group boundary. This keeps groups nonempty and preserves the complete order.

### Scoring fixture expectation history

Expected ranking values follow the scoring specification, not observed code output. Two corrections were made during fixture construction: (1) `low-spread-b` precedes `low-spread-a` by the SHA-256 seeded draw for an otherwise exact ranking tie; (2) the fixture's reveal groups were changed to fixed sizes after the user clarified that tie-breakers complete the order and reveal groups must not move tied entries. The latter changes group boundaries only; the complete ranking and score expectations are unchanged. The scorer excludes any withdrawn or incomplete rater, and assigns each included owner's entry an automatic 10. Neither correction was made merely to match implementation output.


### Visual audit

The home screen was reduced to its title, plain explanation, and direct actions. The three-icon feature row and “Private” badge were removed. Across the implemented routes, icons serve controls and navigation only; the site uses no decorative gradients, floating shapes, marketing card grid, emoji icons, delayed reveal animations, hosted font files, or bundled SF Symbols. Cards remain only where the OSTTracker roster/listening patterns need item boundaries. Recheck new screens against the brief before adding decoration.
